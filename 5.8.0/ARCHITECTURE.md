# 代码架构

原来所有逻辑挤在一个 3,768 行的 `ue58_docs.py` 里。现在拆成分层的 `ue_kb/` 包：
**每一层只依赖它上面的层，不允许反向依赖**。这样改任何一处都能知道会影响谁。

`ue58_docs.py` 保留为兼容外壳，所有老命令照常可用。

---

## 分层

```
                config      常量、路径、分类定义（不依赖任何层）
                  ↓
                 util       时间戳、日志
                  ↓
                  net       HTTP：连接复用、自适应限速、有界重试
                  ↓
                  db        SQLite 连接、表结构、轻量迁移
                  ↓
       ┌──────────┴──────────┐
    discover               htmlmd      站点地图枚举 / HTML→Markdown
       │                      ↓
       │                  chunking     切成小节与知识块、名称标准化
       │                      ↓
       │                 documents     单页抓取 + 结构化转换 + 实体描述
       │                      ↓
       │                    store      落库（小节/知识块/实体/链接/图片）
       │                      ↓
       └──────────┬──────────┘
      crawl / assets / ondemand        全量抓取 / 图片 / 按需补抓
                  ↓
              crossindex               交叉关系构建
                  ↓
          search  →  context           检索 / 受预算约束的上下文包
                  ↓
      export / reports / validate      导出 / 统计 / 验收
                  ↓
                 cli                   命令行入口
```

## 四个关键设计

### 1. 抓取速度：自适应，不写死

Epic 会限流，阈值没有公开。所以 `net.GlobalRateLimiter` 用 AIMD
（和 TCP 拥塞控制同一套思路）自己找上限：

- 连续成功 12 次 → 速率 +0.3 请求/秒（上限 10，实测就在这附近）
- 撞上 429/403 → 速率 ×0.75，并全局冷却（首次 4 秒，短时间内反复被拒才加长）

关键细节：**一次限流事件只降一档**。一次限流会让所有在途请求同时失败，
如果每个失败都降速，速率会瞬间跌到地板再也回不来——第一版就是这么慢到
0.5 页/秒的。`penalize()` 里用"是否已在冷却中"来识别是不是同一次事件。

配套的还有两条：
- 每个线程对每个主机保持长连接，省掉每页一次 TLS 握手。
- 结果攒批提交（每 160 条或 5 秒），不再逐页 `commit()`。

### 2. 检索：五档回退 + 排序融合

见 `search.py` 顶部的表。要点是**不要一上来就用最宽松的匹配**：
先试实体名精确命中，再试短语，再试全含，最后才是任含和前缀。
高精度档已经够用就不再下探，避免宽松结果冲淡答案。

排序不只看 BM25，还叠加：知识类型（签名/概要/参数/返回值优先）、
标题命中率、质量分，并压低庞大的 C++ 成员目录。

### 3. 按需抓取：清单先行

全站清单（199,883 页）在正文之前就冻结了，所以**即使一页正文还没抓，我们依然
知道它存在、属于哪一类、URL 是什么**。这让"用到再抓"成为可能——不用漫无目的
地爬，可以直接命中目标那一页。

定位靠 `pages.normalized_slug`（URL 最后一段标准化后的结果，有索引）：

```
/…/UKismetSystemLibrary/K2_SetTimer  →  k2settimer
用户问 "K2_SetTimer"                  →  k2settimer          ✓
用户问 "Set Timer by Function Name"   →  settimerbyfunctionname
/…/Time/SetTimerbyFunctionName       →  settimerbyfunctionname ✓
```

`ask` 在两种情况下会自动补抓：

1. 本地完全没有结果；
2. 本地虽然有结果，但**清单里有一页正好叫这个名字而还没抓**。
   第 2 条很重要——否则问 `GetCharacterMovement` 时，会拿某篇教程代码示例里
   顺带出现的那一行来作答，而真正的 API 页面就躺在清单里没去取。

补抓后只为新页面建关系（`link_new_pages`），不跑全量 `build_cross_index`——
后者要扫全表，二十万页时得跑几分钟，按需路径付不起这个代价。

### 4. 上下文保护：硬预算

`context.py` 的四条规则：

1. 累计 token 超预算就停，**不存在"最后一条超一点没关系"**
2. 一个页面最多贡献 2 块
3. 内容哈希相同的块只留一份
4. 一跳交叉关系**只给指针**（名称、依据、置信度、展开命令），不塞正文

输出用 Markdown 而不是 JSON —— 同样内容省 30~40% token。

## 测试

```powershell
python -m unittest discover -s tests -v
```

44 个用例，全部离线，覆盖：知识块大小上限、代码围栏切分后仍配对、
别名生成、行内 HTML 清理（且不破坏 C++ 模板尖括号）、检索档位阶梯与
查询形状判定、限速器 AIMD 行为、限流与真失败的区分、302 重定向的特殊处理、
按需抓取的页面定位，以及"落库 → 检索 → 上下文包"的端到端流程
（含预算不越界断言）。

测试会把 `UE_KB_HOME` 指到临时目录，**不会碰真实知识库**。
